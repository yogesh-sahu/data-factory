The flow, step by step

Teal steps already exist in PL_POST_ADD_FUNDINGS. Dashed terracotta steps are the additions — they run before the existing loop, feeding extra rows into the same table.

A1

Fetch what Lender A received Add · GET

Call TMO search-lender-history for Lender A on this loan, window 29 Feb → 5 Mar. Land each payment into a new staging table.

A2

New stored proc inserts one transfer row per payment into fund_adjustment_detail — old lender → new lender, dated on the payment day.

1

Read pending transfers Exists

LOOKUP_POST_FUND_ADJUSTMENT reads every unprocessed row from vw_post_fund_adjustment — now including the catch-up rows.

2

vw_post_fund_adjustment_base turns each row into a − on Lender A and a + on Lender B, grouped into a single JSON array per loan.

3

POST to TMO AddFundings Exists · POST

PL_CHILD_POST_ADD_FUNDINGS sends the whole batch in one call, then marks the rows processed with the API response.

4

Refresh both lenders' portfolios Exists

PL_LOAD_FUND_ADJUSTMENT_LENDER_PORTFOLIO re-pulls Lender A and Lender B from TMO so Azure SQL shows the corrected balances.
